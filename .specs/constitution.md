## Project Identity

- **Name:** Cronshed
- **Description:** A local CLI tool that gives developers full visibility on their cron jobs — execution history, error tracking, next-run calculation, and Telegram alerts on failure. Replaces the opaque `crontab -l` with a structured task manifest and rich CLI commands.
- **Vision:** The natural way to manage personal cron jobs — checked as routinely as `git status`.
- **Stack Reference:** See `.specs/stacks/_default.md`

---

## Architecture Principles

### 1. Simplicity First
- This is a single-user local CLI — no server, no auth, no cloud
- Flat JSON file over database — human-readable, inspectable, editable
- Zero unnecessary dependencies — prefer Bun/Node built-ins

### 2. Single Responsibility
- CLI entry point handles argument parsing only
- Business logic (task CRUD, cron parsing, history) lives in separate modules
- Crontab interaction is isolated in its own adapter

### 3. Explicit Over Implicit
- `tasks.json` is the single source of truth for all task state
- No hidden state — everything is in the manifest or in crontab
- Exit codes are meaningful and documented

### 4. Fail Fast
- Validate cron expressions before writing to crontab
- Validate task names and paths before creating entries
- Report errors clearly to stderr, never swallow them

### 5. No Side Effects at Import
- Modules export functions, not execute on import
- CLI entry point is the only place that triggers side effects
- Test-friendly by design

## Code Conventions

### Naming
- **Files:** kebab-case (`task-runner.ts`)
- **Functions:** camelCase (`getNextExecution()`)
- **Constants:** SCREAMING_SNAKE_CASE (`DEFAULT_TASKS_PATH`)
- **Types/Interfaces:** PascalCase (`TaskConfig`)

### Structure
- Max file length: 300 lines (split beyond that)
- Max function length: 50 lines (extract helpers beyond that)
- Single `index.ts` entry point for CLI

### Runtime
- Bun exclusively — no Node.js fallback
- `Bun.file()` over `node:fs` for file I/O
- `parseArgs` from `node:util` for CLI argument parsing
- No `.env` files — no secrets in this project
